2. QUALITY_FIGURES — JSON with `figures[]` (each figure has a `zone` on the 9-zone grid: `{left|center|right}-{foreground|midground|background}`) and `matches[]` mapping `figure` id → character `reference` name (from matching against reference photos). Authoritative for **who is where**.

   {VISUAL_INVENTORY}

**THE ART STYLE IS PART OF THE SPEC.** The ART STYLE above is the medium this book was commissioned in. The scene description deliberately never mentions it.

Decide ONE thing: does that style call for this KIND of element — glow and light effects, signage and screens, tech and ornament, costume and worn gear, its palette, its rendering medium?

- **Yes → it is never a finding.** Not at any severity, not on any axis. Do not report it as unauthorized, unrequested, unprompted, "not described", extra, added, modern, cluttering, anachronistic, or inconsistent with the era, location, weather or time of day. Do not police the style's own fine print — how many there are, which surface they sit on, whether a sign carries lettering, or whether they suit a rural or period setting. Those are the art director's business, not a defect in this page.
- **No → judge it normally,** exactly as you would any unexpected element. A glowing neon sign in a soft watercolour book IS a defect and you report it.

If no ART STYLE is given above, skip this rule and judge everything normally.

Either way, one thing still counts: a required object, prop or marker REPLACED by a style element, or hidden behind one. Report the MISSING SCENE ELEMENT by name — never the style element that displaced it.

A named character's garment counts only when rendered as a different TYPE or a different BASE colour. Accents, glow, rim light, patterning or a tinted sheen the style implies are the style doing its job — never deduct for those while the garment's type and base colour still read.

---

**ABSENCE RULE — governs STEP 1, STEP 1b and STEP 2 alike. Read it before any of them.**

You have not seen the image. You are reading a written inventory of it, and that inventory reports what it happened to notice — so **its silence is never proof that a thing is not in the picture.**

So: **anything you believe is MISSING is `unverified_absence`,** whether it is a prop, a landmark, an animal, a garment, an accessory or a facial feature. That type exists to keep the observation on the record without letting a claim you cannot check carry a full deduction. Never file an absence as `missing_element`, `clothing`, `character_identity` or `accessory_missing` — those say "I confirmed this is gone", and you cannot.

**One exception, because it rests on evidence rather than silence:** `missing_character` in STEP 1, where the test is not "absent from the inventory" but "absent from `QUALITY_FIGURES.matches[]` AND no plausibly-matching inventory figure". That is a comparison of two inputs, not an inference from a gap — keep it, still capped at MAJOR.

Wrongness is a finding; absence is a guess. When the inventory NAMES the item and describes it differently from the brief, that is a real comparison and you report it normally at its own type.

**STEP 1: PAIR FIGURES BY ZONE**

**PRESENCE IS AN INPUT — never your judgment.** `QUALITY_FIGURES.matches[]` already identified who is in the image (via reference-photo matching upstream). A character listed there IS present and correctly identified. You may NEVER flag such a character as missing, `missing_character`, or "no inventory figure matches" — no matter how their hair, freckles, ponytail side, clothing pattern, expression, or any appearance detail differs. Appearance differences on a present character are reported in STEP 2 as per-character issues, never as absence.

For each `matches[]` entry in QUALITY_FIGURES, take the figure's zone from QUALITY_FIGURES.figures[]. Find the VISION_INVENTORY figure in the same zone (or the nearest one — do not require an exact zone match) and output a pairing `{name, label, zone, vision_description}`, carrying that figure's VISION_INVENTORY label verbatim. Zone mismatch is a position note, not an absence.

The ONLY case for `missing_character`: a character named in ORIGINAL_PROMPT that has NO entry in `QUALITY_FIGURES.matches[]` AND no plausibly-matching VISION figure at all. If they are in `matches[]`, they are present — stop. `missing_character` is at most MAJOR, never CRITICAL — you have not seen the image, so an absence you infer from the inputs is a report, not proof.

If `matches[]` is empty or absent while figures exist in QUALITY_FIGURES or VISION_INVENTORY, the upstream identification step failed — it did NOT determine that anyone is missing. In that case pair prompt-named characters to inventory figures by zone and appearance (age group, hair, clothing) as best you can, and never emit `missing_character` for a character with any plausibly-matching figure. Do not report "character not identified in matches[]" as an image defect at all — a gap in the identification input is an eval-input deficiency, not something wrong with the picture.

---

**STEP 1b: SCENE CHECK**

- Extra inventory figures with no pairing: flag only if ORIGINAL_PROMPT describes a solo or small-group scene; ignore for crowd/marketplace/villagers.
- Are all requested objects/animals/landmarks present per VISION_INVENTORY? The inventory lists what it judged NOTABLE, so a small or partly hidden prop can be real and unlisted. An item you cannot find there is `unverified_absence` — per the ABSENCE RULE above — never `missing_element`. If the inventory DOES name it and describes it wrongly (wrong object, wrong place, wrong size), that is a comparison you can actually make: report it at its own type.
- Supporting figures the prompt explicitly places with a role and location (guards inside a vehicle, a sentry at a gate, a crowd surrounding the hero) not found in the inventory → `unverified_absence`; you are inferring their absence from a list, not seeing an empty gate. Ambient decoration ("a few passersby", "busy street") absent → no deduction at all.
- Is the setting/environment correct? Judge it in the ART STYLE the ORIGINAL_PROMPT names — rendering the style calls for (palette, glow, atmosphere, light sources, and physical ambience the style mandates, e.g. era machinery woven into walls, architecture and fixtures) is never a setting mismatch. This holds for real, named landmarks too: the landmark must stay recognizable, but style elements added onto it are intended, never a deviation from its description.
- Implausible placement: if VISION_INVENTORY's standing-surface or physics check reports a figure standing where a person would not stand — in water, inside a fountain/pond/basin, inside a solid object, on furniture, or floating — and the prompt did not call for it, flag it `implausible_placement` CRITICAL for a named character.

**STEP 2: CHARACTER COMPLIANCE (per paired row)**

For each paired row from STEP 1 with a non-null `vision_description`:
- **Undressed figure**: CATASTROPHIC, `type: "nudity"` — a last-resort safety net that should almost never fire. Report it ONLY when the inventory describes a figure with NO garment on the lower body AND none on the torso. Shorts, briefs, bloomers, underwear, swim trunks, a swimsuit, a skirt or trousers all mean it is NOT nudity, however brief and however wrong for the scene — a bare chest above any lower garment is never nudity, and neither are bare arms, bare legs, bare feet, or a swimming scene. Occlusion, cropping, water and blankets are not nudity. Too little clothing, or different clothing from the brief, is a **clothing** finding instead. When in doubt it is not nudity.
- **Clothing type**: Vision clothing vs the CLOTHING CONTRACT; fall back to the prompt only when the contract is empty. An outfit matching its contract line is never a finding, whatever the era, location or theme suggests a character should wear. Modern clothes (sweatshirt, jeans, sneakers) when the contract names a costume = CRITICAL. Wrong main colour = MAJOR. This bullet is for WHICH garment it is — nothing else.
- **Clothing detail**: the right garment, cut or worn differently — sleeve length (long where short was named, or the reverse), rolled or unrolled sleeves, collar shape, cuff, hem, a button or pocket. `clothing_detail`, MODERATE, never higher, ONE entry per figure. The inventory describes garments in its own words and a sleeve is the detail it is least reliable about; a rolled sleeve is not a costume failure. Do not restate it under `clothing`.
- **Accessories**: small worn items — eyewear, hat, bandana, belt, sash, badge, footwear, jewellery, watch, hairclip. Never CRITICAL, whatever the prompt said. A wrong VERSION of one (bicorne for tricorn, gold trim for white, trainers for slip-ons) is `accessory` MODERATE — the inventory named the item, so you are comparing two descriptions, not inferring. One entry per figure covering every accessory deviation on that figure — never one finding per item. A missing accessory follows the ABSENCE RULE at the top: `unverified_absence`, including when the inventory's eyewear / headwear / facial-hair / worn-items field says `none visible` — that field is itself an inference by a stage that has called an eye patch "black sunglasses".
- **Hand and limb precision**: never deduct for which hand performs an action, precise finger or palm placement, a limb resting differently than described, or contact at a slightly different height or point on the same object. The inventory cannot resolve this reliably and a correctly-formed limb that rests differently is not a defect. Only a limb contacting a different OBJECT than the prompt names is a finding.
- **Age appearance**: Vision age group vs prompt.
- **Hair**: Vision hair vs prompt.
- **Position**: Horizontal half (left vs right) is a mirror — never deduct. Different depth only (foreground vs midground) = no deduction either.
- **Left vs right is a mirror in EVERY form — never deduct, under any code.** This covers more than where a figure stands: which way a figure FACES or is turned (facing right where the prompt says left, and the reverse), which side of the body a limb acts with, and which side of the body a worn item sits on (an eye patch, a bag strap, a badge on the left vs the right). A mirrored composition is the same composition. Front vs back is a different question and IS judgeable: back to camera where the prompt wants a face, or a face where the prompt wants a back view. Never turn a mirror into a finding by pairing it with the prompt's wording ("prompt requires him facing left") — the prompt's left is mirror-equivalent too.

---

**STEP 3: INTERACTION CHECK**

For each declared interaction, ask: could the inventory figure plausibly be doing this action? Use VISION_INVENTORY's interaction lines, resolving each label to the name it paired with in STEP 1. Don't judge pose precision, angles, or gesture nuance.

Only flag a contradiction:
- Declared "holds X" / wears X / X in hand, inventory says hands empty or X missing → CRITICAL
- Declared "sits / kneels", inventory says standing → MAJOR
- Declared action toward Y, inventory shows the figure turned the opposite way with no matching gesture → MAJOR
- Declared object entirely missing from inventory → CRITICAL
- Object placement in a genuinely different category (declared "in pocket", drawn as large held object; declared "on head", drawn "in hand") → CRITICAL. Left/right mirror differences are equivalent and do NOT flag. Mirror equivalence covers body sides and frame halves only — a limb declared to contact one surface but rendered contacting a different object is a real contradiction, not a mirror.

If the inventory is roughly compatible with the declared action, do not deduct. Pose details in the scene prose that are NOT in DECLARED INTERACTIONS (hands drawn in tight, fingers curled, jaw set) are descriptive only — do NOT deduct. Extra background figures in populated scenes (crowd, vendors, villagers, passersby) do NOT deduct.

---

**IGNORE** (do not deduct for these):
- Exact object colors (lilac vs purple, crimson vs red) — only clothing type/category and fully wrong clothing colour matter.
- Depth labels (foreground / midground / background).
- Small position drift (left-of-center vs center).
- Exact pose, gesture, or framing.
- Motion verbs in the prose (walking, running, approaching, scanning). A still image cannot show motion; any frozen pose satisfies them.
- Direction of travel of a mid-motion figure (leaping, falling, diving). A frozen pose cannot show which way the figure moves; an inventory phrase like "jumping from X toward Y" is inference, not observation. Judge only which surfaces and objects are visibly touched.
- Internal-state claims ("appears thoughtful", "looks distracted").

---

**STEP 4: SEVERITIES**

A character present in `QUALITY_FIGURES.matches[]` is never "missing" — appearance differences on them are per-character issues (wrong age = MAJOR, wrong hair = MAJOR), never CRITICAL missing-character. Do not bundle several appearance differences into one entry: one deviation = one entry, each severitied on its own. The single exception is accessories, which STEP 2 collects into one entry per figure.

**One defect, one entry, one code.** Each finding names exactly one problem and carries the code for that problem. Never restate a second defect inside a finding about something else — a facing finding describes facing and nothing else, even when the same figure is also dressed wrongly. The wardrobe is its own entry under its own code. Charging a defect a second time inside another finding double-counts it, because the pipeline scores every entry.

**NEVER CRITICAL — these are never a CRITICAL, and usually not a deduction at all. Check every finding against this list BEFORE tagging it CRITICAL:**
- Left vs right anything — which hand grips, which arm reaches, which side a figure stands, which hand holds what. Mirror. Ignore entirely.
- Motion verbs — running, walking, approaching, striding, leaping, reaching. A still image cannot show motion; a frozen pose satisfies "runs out", "walks toward", "reaches". Do NOT deduct. (A declared *stance* — sitting, kneeling — rendered as standing is a real pose difference, but it is at most MAJOR, never CRITICAL.)
- Expression, gaze direction, head tilt, smiling-vs-serious — at most MODERATE, never CRITICAL.
- Background or setting detail — a fence's type or material, path surface, an added tree, a building's placement, wall colour, lighting, sky, or a missing background prop.
- Anything the supplied ART STYLE calls for. Not merely "never CRITICAL": never a finding at all, at any severity. That style outranks real-world plausibility for the era, the location and the time of day, so it is never anachronism, never a setting mismatch, never wrong lighting, never unauthorized or unrequested, and never something to remove. Applies only to THAT style — an element it does not call for is judged normally.
- Clothing pattern, print, decoration, or a single wrong colour — at most MAJOR for a fully wrong main colour.
- A prompt-named character absent from `matches[]` — identification happens upstream and its gaps are input deficiencies, not image defects. With a plausibly-matching inventory figure: no finding at all. With no plausible figure either: `missing_character` at most MAJOR.

**Lettering.** The inventory's Lettering section reports what is painted in the image. Report `rendered_text` when it names a caption or watermark laid over the art, unreadable scribble letterforms, or words on a surface that neither ORIGINAL_PROMPT nor the ART STYLE asked for. A string the prompt quotes, and lettering the style calls for, are correct.

**Figure height.** ORIGINAL_PROMPT may carry a HEIGHT ORDER line. Report `scale`, at most MAJOR, when the inventory ranks figures standing at the same distance in an order that plainly contradicts it — the named tallest reported as shortest, or a figure reported clearly taller than one it must be shorter than. Adjacent names, `roughly equal`, and any figure the inventory marked `cannot tell` are not findings.

**Object colour.** The inventory reports each object's colour and material. Report `object_presence` when a named object's colour clearly differs from the colour ORIGINAL_PROMPT gives it — at most MAJOR. A different shade of the same colour, and anything the inventory marked `cannot tell at this size`, are not findings.

Tag each `fixable_issues[]` entry with a severity — the pipeline computes the deduction from these tags:
- CATASTROPHIC: an undressed figure (`nudity`, see STEP 2) — cannot be published
- CRITICAL: Clothing completely wrong TYPE (modern vs medieval/costume), declared interaction object missing or in a genuinely different category (held-vs-pocket-vs-on-head — NOT left arm vs right arm), extra limbs, floating figure, `implausible_placement` (a named figure standing in water, inside a fountain/pond/basin, or inside a solid object the scene did not call for), `wrong_action` (main beat intent contradicted by inventory — e.g. prompt says offering, inventory shows aiming; never based on direction of travel inferred from a mid-motion pose)
- MAJOR: Missing character (named in ORIGINAL_PROMPT, absent from `matches[]`, AND no plausible VISION figure — never higher than MAJOR: absence inferred from inputs is a report, not proof; the image-seeing evaluator owns confirmed absences), character facing the wrong way for a DECLARED INTERACTION (e.g. two characters declared as interacting but facing away from each other; character declared as watching a named object but looking elsewhere), wrong clothing colour (as `garment_colour` — a right-type garment in the wrong main colour has its own mechanical recolour), wrong age appearance, cross-eyes
- MODERATE: Minor clothing detail, key object missing
- MINOR: Small differences

Do not report a score. It is computed from the severity tags on your findings. VERDICT is one of PASS / SOFT_FAIL / HARD_FAIL and is display-only.

**RULES:**
- Output ONLY JSON
- Base ALL assessments on the visual inventory, NOT assumptions
- Clothing TYPE mismatch (modern vs costume) is CRITICAL, not just a color issue
- Facing direction is as important as clothing — characters must face what they interact with
- `fixable_issues`: ONE entry per issue found — the code decides the repair method (inpaint, regenerate, character-fix)
- `type` on every entry MUST come from this closed list. The value routes the repair; anything else is discarded as unroutable, so the defect is reported and then never fixed:
  `action_interaction` (wrong or missing declared interaction, wrong main action, wrong pose, and ORIENTATION — a figure turned away from the person or object it is engaging; never an axis, never left vs right) · `missing_character` · `missing_element` (a named object, animal or landmark absent) · `object_presence` (present but wrong, misplaced or unrequested) · `object_count` · `setting` (wrong location, background, weather or time of day) · `character_identity` (wrong person, age, or hair) · `clothing` (which garment TYPE it is) · `garment_colour` (right garment type, wrong main colour) · `clothing_detail` (right garment, different cut: sleeve length, collar, cuff, hem) · `accessory` (small worn item rendered as the WRONG VERSION — never for one you believe is absent) · `unverified_absence` (ANY absence — you have not seen the image, so every absence you report uses this type) · `scale` · `figure_completeness` · `anatomy` · `rendered_text` · `character_marking` · `anachronism` · `image_coherence` · `naturalness` (anything else)
  ONE type per entry. Never invent a value. Never join two with an underscore, comma or slash — if a finding needs `pose_and_position` or `clothing, prop`, it is two findings or the wrong one.
