# CLOTHING REQUIREMENTS

Determine which clothing variants each character needs, based on the beats.

- Mark `used: true` only for variants that actually appear.
- Set `costumed.used: true` whenever the theme, setting or era implies special clothing, and name it in `costumed.costume` (`medieval`, `wizard`, `pirate`, `firefighter`, `1920s`, …). Leave it false only for a present-day story in everyday clothes.
- If any character is costumed, every cover uses the costumed variant for every cover character.
- `description` is the FULL final outfit for this story — top, bottom, footwear, accessories — as one self-contained sentence. Start from the character's stored clothing above; keep it, add a story-relevant accessory, or change a garment the story requires. The avatar generator uses it verbatim.
- Costumed descriptions state every slot: headwear (or `none`), top, bottom, footwear, belt/waist, outer layer (or `none`). Each slot names colour and material. Clothing only — no pets, carried objects or bag contents.
- Name structural garment parts, not just the garment. Dungarees, pinafore, suspenders, kilt, kimono, sari and similar render as plain garments when only named: keep the garment name in front and spell out its parts ("denim dungaree shorts — square bib panel over the chest held by two shoulder straps").
- No headwear, helmets, crowns or masks that cover the face.
- Costumed characters must differ from each other in all three: dominant colour word, silhouette (garment type, length or cut), and two costume signature elements a child would name at a glance. Colour-only variation fails.
- Never write `none`, `n/a`, `tbd` or `""` as a value. Omit the field instead. `used: false` carries no `description`.

# VISUAL BIBLE

Scan the beats and list every element that must stay consistent across illustrations. An element a beat only implies still needs an entry — the scene writer can only reference what is listed here.

- All locations, all objects, all vehicles, all animals, all worn costumes and garments.
- Secondary characters you invented only. Never {CHARACTER_NAMES} — they have reference photos.
- English `name` and `description` for artifacts, locations, vehicles and clothing, even for a non-English story; those strings are copied into English image prompts. Characters and animals keep their given names.
- Every item in exactly one category. A worn garment belongs to `clothing` only, never also to `artifacts`.
- At least {PAGE_COUNT} entries. Include an element even if it appears once.
- Empty categories are `[]`.
- One entry per secondary character, no matter how the beats refer to them; a person named both by relation and by attribute is one entry. Never reuse an id.

Every entry needs specific colours, one signature element, and a description that works without seeing the other scenes.

The `description` is copied verbatim into image prompts, so write it as image-prompt text:
- Describe the SHAPE for objects the model confuses — name the parts and how they connect (`perpendicular`, `parallel`, `spans across`, `forms a T from above`, `mounted at right angles to`). No analogies, no negations; both mislead the model.
- Name every functional part the model tends to drop, with its position and state (a taut string, evenly spaced rungs, a tensioned sail).
- For a prop with visible writing, either quote the exact text or call it illegible / weathered / smudged. Never say text is visible without naming it.

Ids: CHR001… secondary characters, ANI001… animals, ART001… artifacts, LOC001… locations, VEH001… vehicles, CLO001… clothing.

Real-world landmarks get `isRealLandmark: true` and `landmarkQuery` set to the exact name from the available landmarks list.

A location shown from one viewpoint needs no `vantages[]`. Give it `vantages[]` and split it when the same place appears from a fundamentally different camera position — exterior/interior, on a structure/beside it, wide vista/close on one element, approach/arrival. Do not split for lighting, weather, time of day or a different cast. Vantage ids are `LOC###.N` from 1; each carries `name` (3-8 words), `shot` (`wide|medium|close-up|wide-low|aerial`), a 2-3 sentence background-only `description` naming the empty foreground band for characters, and `pages`. Every page in the location's `pages` appears in exactly one vantage.

# COVER SCENE HINTS

Each cover is a structured spec, not prose. The fields are the spec.

- The first entry in `Objects:` is the backdrop and must be a LOC### from the Visual Bible. The Title Page backdrop must be a real landmark whenever the Visual Bible holds one; Initial Page and Back Cover prefer one. Never invent a LOC for a cover.
- List every character by name. Never "the family", "everyone", "the group".
- Clothing is one of `standard | winter | summer | costumed` and must be a category that character marked `used: true`.
- `holds` is exactly one ART### from `Objects:`, or the word `nothing`.
- `priority` is `essential | normal | low`.
- `Mood` is one phrase of 2-5 words.
- No perspective or depth on covers — every figure faces the viewer and is fully visible. If the cast does not fit, drop the least essential character instead of hiding them.

Title Page: only {MAIN_CHARACTER_NAMES}.
Initial Page and Back Cover: up to 5 characters from {MAIN_CHARACTER_NAMES} and {PRIMARY_CHARACTER_NAMES}, always including the main characters. Over 5, drop the least important primary characters entirely.
