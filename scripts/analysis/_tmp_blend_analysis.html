The blend prompt: what is wrong with it, and three ways out

Everything below is measured against the exact prompt that ran in Lab exp 848 (5451 chars, 41 lines) and the image it produced — a duplicated character and a re-framed shot, on a page where every step before the blend was correct.

Two are outright bugs — a blind mid-word truncation and a reference to an image that was never attached. Three are internal contradictions, where the prompt asks for opposite things in two places. Five are structural, and no amount of extra prompt text will fix them: the two failures exp 848 actually produced were both already forbidden, in writing, in that prompt.

The ten faults

BUG

1. THE SCENE is cut mid-word at exactly 900 chars

sceneComposite.js:1704 — .slice(0, 900). The block ends "…chin-length straight bl". Sarah's description dies mid-sentence and Hans never appears in that block at all. The prompt measured 5451 chars against an 8000 cap — 2549 chars of headroom, so nothing forced the cut.

It is the blind-cut pattern already logged as an incident: images.js:635-642 records a 9.4k prompt cut at 7.5k that "lost its entire ART STYLE block and rendered photographic on every roll (3/3 measured)". The plate builder next door does this properly via shrinkSetting, which measures and protects. The blend does not.

BUG

2. The prompt cites an Image 2 that was never attached

"Faces, hair, age and clothing stay as Image 1 and the labelled portrait grid show them." That page has no grid — visualBibleGrid absent, hasVisualBibleGrid undefined, zero grid rows in story_images. So blendRefs was [composited] alone.

The one instruction anchoring identity points at an image that is not in the call. A dangling reference does not merely fail to help — it invites the model to supply the missing reference itself.

CONTRADICTION

3. "cinematic composition" invites the re-framing the DO-NOT forbids

Art style block: "…warm natural light, real-world textures, cinematic composition." DO NOT block: "Do not re-frame: same camera distance, same borders, same crop."

Composition IS framing. The style line asks for a well-composed shot and the constraint forbids changing the shot. In exp 848 the camera pulled in and cropped out the bridge and tower — the style line won. This is the same class of defect as the one 3ad9e1a12 just fixed: two clauses in one prompt asking for opposite things.

DESIGN

4. Four different edit classes in one pass

Turn bodies · adjust heads, arms and hands · repaint faces to named expressions · soften edges, match light, add contact shadows.

A single Grok edit call is being asked to do a pose pass, an expression pass and a compositing pass at once. The more simultaneous latitude a whole-frame edit is given, the more it re-imagines rather than adjusts.

DESIGN

5. The constraints are negations, and the two that mattered were ignored

Four DO NOT bullets. Exp 848 added a character (forbidden explicitly) and re-framed (forbidden explicitly).

Both failures were already named in the prompt. Adding more prohibition text cannot fix a failure whose prohibition is already there and already ignored — image models weight negation poorly, and naming a thing can prime it.

DESIGN

6. The change signal is duplicated; the preservation signal is not

Each character's action appears twice — once as doing: under WHO IS IN THE PICTURE and again under CHANGE THESE. Clothing appears twice — once in THE SCENE, once as wearing:. "kneels at the gap in the bridge railing" appears twice; "stands at the water" appears twice.

Roughly a third of the prompt is restated content, and what gets restated is what to CHANGE. "Do not move anyone" is said once.

CONTRADICTION

7. Repaint the faces, but keep the faces

"repaint their faces so that each one is doing what the scene asks" versus "Faces, hair, age and clothing stay as Image 1."

Both are wanted — new expression, same identity — but the prompt states them as a flat contradiction and leaves the model to find the seam.

DESIGN

8. The occlusion clause never names the occluder

"something in the scene crosses in FRONT of them, so only part of them shows." The occluder is the bridge parapet, and the prompt knows it — the same prompt says Daniel kneels "at a gap in the bridge's railing".

The model must infer which element is doing the hiding before it can preserve the relationship. In 848 it resolved the ambiguity by drawing a second, unoccluded Daniel.

DESIGN

9. The key spatial constraint is the last line, after the art style

"Depths as staged: Daniel is in the background — small and distant…" sits below the style block, detached from the WHO block it describes.

The one line that pins relative size is orphaned at the bottom, while per-character depth already appears in WHO as prose ("in the distance"). Two half-statements in two places instead of one authoritative one.

DESIGN

10. The prompt is framed as a deficit, not as a target

It opens: "What is wrong is that they were pasted in: they stand stiff, blank-faced and disengaged."

It tells the model the picture is broken, then hands it the whole frame. A model told an image is wrong is licensed to fix whatever it judges wrong — including the framing and the cast.

Three ways to do it better

These are not variations on wording. Each changes what the model is allowed to touch — because the evidence says wording alone is not the lever.

AMasked per-figure edits — make the violations impossible

Stop editing the whole frame. Run one small masked edit per figure, confined to that figure's bounding box, with a two-line prompt: the action, the expression, and "match the surrounding light". The background, the framing and the cast list are physically outside every write region.

fixes
1, 3, 4, 5, 8, 10 — re-framing and character-duplication become structurally unreachable rather than forbidden by text.
leaves open
Identity anchoring still needs the grid (issue 2) attached per-crop.
cost
N calls instead of 1. Three figures = 3 edits ≈ the same $0.06, but more wall-clock. Edge blending has to come from the existing feathering rather than the model.
risk
Per-figure edits cannot produce cross-figure interaction (two characters looking at each other reads as two independent edits). Seams at mask borders. The machinery exists — faceRepair.js and samBlend.js both do masked writes with the 70%-revert guard.

BDescribe the finished picture, not the repairs

Rewrite as a single positive description of the output, in the shape of an ordinary generation prompt: "A photograph of a woman at the water's edge in the left foreground…, an elderly man in the middle distance…, and a small distant man kneeling behind the bridge parapet, only his upper body visible above it. Same framing as the input image." No DO-NOTs, no deficit framing, no repeated action lines, occluder named, depth stated once inside each character's own sentence.

fixes
3, 5, 6, 7, 8, 9, 10 — every contradiction and the entire negation dependency.
leaves open
Still a whole-frame edit, so re-framing stays possible in principle — it just is not being invited any more.
cost
One prompt rewrite. Same 3 model calls, same $0.06 per run. By far the cheapest to test.
risk
Least structural. If Grok re-frames anyway, this tells us the whole-frame blend is unsalvageable — which is itself a decisive answer worth $0.06.

CTwo passes, one job each: pose+face on crops, then a 3-line settle

Pass 1 edits each figure on a tight crop (pose and expression only — no scene text at all, so nothing to re-frame), pasted back. Pass 2 is a whole-image call whose entire prompt is: soften the pasted edges, match everyone to the scene light, add contact shadows. No characters named, no actions, no depths, nothing to re-interpret.

fixes
3, 4, 5, 6, 7, 9, 10 — each call gets one job and a prompt short enough to have no room for ambiguity.
leaves open
Crops still need identity refs (issue 2).
cost
N+1 calls. Four figures = 5 calls, roughly double today. Call it ~$0.10-0.12 per page.
risk
The most work to build. But it is the only option that keeps a genuine global blending pass while removing every reason for that pass to touch content — the settle prompt would be short enough to read in one breath.
Regardless of which: fault 1 and fault 2 are bugs that should be fixed under any of the three, and both are small. Fixing them alone changes what the model sees — the blend has never yet run with a complete scene description or an identity reference attached, so no verdict so far has tested the prompt as designed.
